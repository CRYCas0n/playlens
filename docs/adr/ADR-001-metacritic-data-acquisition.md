# ADR-001 — Источник данных Metacritic и изоляция зависимости от него

**Статус:** принято · 2026-09-06
**Заменяет:** `BLUEPRINT.md` Приложение B, ADR-0001 и ADR-0002 (подтверждает и уточняет)
**Связанные противоречия:** C-24, C-01, C-03, C-04

## Context

ТЗ требует собирать данные с `https://www.metacritic.com/game/` (New Releases) и
`https://www.metacritic.com/browse/game/all/all/all-time/new/`. Исследование
(`BLUEPRINT.md §2.1`) установило фактами:

- Сайт — Nuxt 3 SPA. `__NEXT_DATA__` нет, JSON-LD на хабе нет; в HTML есть только
  devalue-сериализованный `window.__NUXT__` и сгенерированные Tailwind-классы. CSS-селекторы
  по ним сломаются при первом редизайне.
- Существует внутренний JSON API `backend.metacritic.com`. `apiKey` **не валидируется**
  (200 без ключа и с неверным ключом), UA не проверяется, 20 параллельных запросов прошли
  без 429. Ответы кэшируются Cloudflare.
- На страницах **отдельных игр** есть ровно один блок `application/ld+json` со схемой
  `VideoGame` — пригодный fallback.
- `robots.txt`: целевые пути `/game/*` и `/browse/game/*` **не запрещены**; `Crawl-delay`
  не задан. Полный `Disallow: /` есть для 14 именованных ботов, включая GPTBot.
  `backend.metacritic.com` — другой хост, robots.txt его не покрывает.
- ToS Fandom запрещает автоматизированный сбор данных.

Открытый вопрос Q1 блюпринта («допустимо ли использовать internal API») формально не был
закрыт заказчиком.

## Decision

1. **Первичный источник — внутренний JSON API** `backend.metacritic.com`, за интерфейсом
   `MetacriticSource`.
2. **Вторичный источник — `HtmlSource`** за тем же интерфейсом: JSON-LD `VideoGame` →
   OpenGraph → `data-testid`-якоря. **CSS-селекторы по Tailwind-классам запрещены** —
   это правило проверяется линтером репозитория (grep по запрещённым паттернам в тестах).
   Переключение — переменная `METACRITIC_SOURCE=json_api|html`.
3. **Ни одна зависимость от internal API не выходит за пределы `app/adapters/metacritic/`.**
   Бизнес-логика видит только `MetacriticProvider` и DTO. Это проверяется тестом-архитектурным
   правилом: `app/services/**` не импортирует `httpx` и не содержит строк `backend.metacritic`.
4. **Вежливость зашита в дефолты конфига, а не в договорённость:** `METACRITIC_RPS=2.0`,
   `METACRITIC_MAX_CONCURRENCY=2`, идентифицируемый User-Agent с контактным URL, уважение
   `Retry-After`, экспоненциальный backoff с джиттером, circuit breaker.
5. **Дисклеймер обязателен и виден**: в `README.md`, на странице `/about`, в футере каждой
   страницы. Продукт не выдаёт себя за первоисточник; на каждом блоке — ссылка на Metacritic.
6. Пагинатор не доверяет параметрам API (см. ADR-005), а полнота листинга страхуется
   sitemap-сверкой (см. ADR-004).

## Alternatives considered

| Вариант | Почему не выбран |
|---|---|
| Только HTML-парсинг `www` | Хрупко (Tailwind, Nuxt-payload), 969 КБ на страницу вместо типизированного JSON, и **не даёт** per-platform Userscore вообще |
| Playwright / headless-браузер как основной путь | JS для получения данных не нужен — доказано: `curl` с дефолтным UA получает 200 и от `backend`, и от `www`. Браузер в образе — сотни МБ ради гипотетического будущего. Оставлен как описанная точка расширения `BrowserSource` |
| Отказаться от Metacritic, взять официальный источник | Официального API у Metacritic нет. Альтернативные агрегаторы не покрывают требование ТЗ |
| Использовать `apiKey` из фронтенда как «свой» | Ключ не валидируется, то есть он не является ни секретом, ни средством авторизации. Мы его передаём как есть (он публичен в их HTML), но **не полагаемся** на него и не подделываем HMAC-подпись CDN для ресайза изображений — это уже выход за рамки допустимого |

## Why

Типизированный JSON вместо парсинга генерируемых классов радикально снижает класс ошибок
«схема уехала — данные молча испортились»: Pydantic-модель с `extra='ignore'` терпит
добавление полей и падает `SchemaDriftError` на исчезновении обязательных.
Одновременно единственный реальный риск (R1: API закроют) закрывается не обещанием,
а работающим вторым адаптером и nightly contract-тестами.

Вопрос легальности не игнорируется: он вынесен в `OPEN_QUESTIONS.md` как **OQ-B3** с явным
условием — публичная или коммерческая эксплуатация требует отдельного решения владельца.

## Consequences

- Стоимость сбора одной игры: `1` (composer) `+ N` (user stats на платформу) `+ R` (страницы
  отзывов, по 10 у критиков). Это заметно дороже, чем предполагал ранний блюпринт.
- В `.env.example` `METACRITIC_API_KEY` присутствует как **публичное** значение с комментарием,
  что это не секрет; он не логируется наравне с прочими ключами и не обязателен.
- Появляется обязанность держать `HtmlSource` живым: он покрыт фикстурными тестами
  с первого дня, иначе к моменту, когда он понадобится, он не будет работать.

## Risks

| Риск | Митигация |
|---|---|
| API закроют или начнут требовать подпись | `HtmlSource` + авто-переключение по порогу `SCHEMA_DRIFT_THRESHOLD` + алерт |
| Смена `apiKey` во фронтенде Metacritic | Ключ не валидируется, поэтому смена не ломает нас; contract-тест сверяет и предупреждает |
| Cloudflare-challenge с датацентрового IP | **Не проверено из этой среды.** Validation-задача OQ-V2. При провале — `BrowserSource` или прокси, оба за тем же интерфейсом |
| ToS-претензия | Дисклеймер, атрибуция, консервативный rate limit, отсутствие публичного доступа по умолчанию, готовность отключить |
