# ADR-015 — Глубина каталога и правило eligibility

**Статус:** принято · 2026-09-06
**Связанные противоречия:** C-16

## Context

Исследование дало два числа:

- `finder` без фильтра оценки: **177 882** игры;
- `finder` с `metaScoreMin=1`: **18 524** игры.

При лимите ТЗ в 20 игр за часовой прогон: полный обход — ~370 суток, обход игр с Metascore —
~38 суток.

`BLUEPRINT.md §28 Q4` оставил это вопросом заказчику с рекомендацией «ограничиться играми
с Metascore — остальные 90% каталога это шлак-приложения без оценок и отзывов, на них нечего
суммаризировать».

Задание §29 требует: правило не должно быть скрытым. Нужно явно зафиксировать, что такое
eligible game, что происходит с играми без оценки, может ли пользователь их найти, и что
относится к будущей reconciliation.

## Decision

### Eligible game = игра, у которой есть Metascore

Обе фазы discovery используют `metaScoreMin=1`:

| Фаза | Запрос |
|---|---|
| New Releases | `componentName=new-releases-carousel&sortBy=-releaseDate&metaScoreMin=1&mcoTypeId=13` |
| browse | `sortBy=-releaseDate&metaScoreMin=1&productType=games&offset=...` |
| seed | `sortBy=-metaScore&metaScoreMin=1&productType=games` |

Обоснование: продукт — decision assistant поверх мнений. Игра без единой рецензии критиков
не даёт ни вердикта, ни резюме, ни объяснения gap'а, ни осмысленной похожести. Она стоит
столько же в обходе и не производит ничего из того, ради чего существует сервис.

### Игры без Metascore при этом полностью поддержаны

Правило eligibility — про **обнаружение**, а не про хранение и не про отображение.

| Ситуация | Поведение |
|---|---|
| Игра попала в базу через sitemap-сверку и не имеет оценок | Хранится; рендерится как `Not rated` (`—`, серое кольцо) — дизайн это предусматривает, фикстура `orbital-freight-simulator` |
| Игра потеряла Metascore после обновления данных | Остаётся в базе, оценка становится `UNAVAILABLE`; не удаляется |
| Пользователь ищет такую игру по названию | **Находит.** Поиск не фильтрует по наличию оценки |
| Пользователь листает каталог | По умолчанию сортировка `Metascore, high to low` уводит их в конец; фильтр score-band `Not rated yet` (`design/COPY.md §5`) показывает их явно |
| Похожие игры | Штраф `x0.35`, если у обеих нет оценки и мало отзывов (ADR-011) — не рекомендуем пустышки |

**Отдельного флага `is_eligible` в схеме нет.** Он не нужен: наличие оценки — это уже
атрибут данных, а не отдельная бизнес-сущность. Меньше состояний — меньше расхождений.

### Что относится к будущему

- Полный обход 177 882 игр — **не входит** в текущий объём. Возможен как отдельный
  долгий backfill, но требует отдельного решения о стоимости и объёме БД.
- Sitemap-сверка (ADR-004) уже сегодня приносит slug'и без фильтра оценки, с лимитом
  `RECONCILE_MAX_NEW` за прогон. Это и есть контролируемый канал расширения каталога
  за пределы eligible-множества.

### Видимость правила

- Записано здесь, в `CONTRADICTIONS.md` C-16 и в `FINAL_SPEC.md §29`.
- Видно в мониторинге: параметры источника прогона логируются в `crawl_runs.source_params`.
- Видно пользователю косвенно: страница `/about` объясняет, какие игры индексируются;
  пустой результат поиска содержит фразу «We index games from Metacritic, so very new or
  very small releases may not be here yet» (`design/COPY.md §8`).

## Alternatives considered

| Вариант | Почему не выбран |
|---|---|
| Обходить весь каталог (177 882) | ~370 суток при лимите ТЗ; 90% — приложения без оценок и отзывов, для которых продукт не производит ничего |
| Ограничиться New Releases (20 позиций) | Каталог не растёт; похожие игры не работают; ТЗ §2 прямо требует browse-фазу |
| Ввести `games.is_eligible` и фильтровать по нему в API | Лишнее состояние, которое надо поддерживать в актуальности при каждом изменении оценки. Наличие `best_metascore` даёт то же самое бесплатно |
| Скрывать игры без оценки из каталога полностью | Пользователь, пришедший по прямой ссылке или из поиска, увидит игру, которой «нет» в каталоге — необъяснимое поведение |
| Порог `metaScoreMin=60` (только хорошие) | Продукт про решение, а не про рекламу. Плохие игры — самая полезная часть выборки для персоны «сомневающийся» |

## Consequences

- Целевой размер каталога — 18 524 игры; при 20 в час это ~38 суток непрерывной работы,
  ускоряемых seed-обходом.
- Объём БД оценивается по этому числу: ~18.5k игр × ~2 платформы в бюджете × (до 200 critic +
  до 500 user отзывов) — верхняя граница в единицы десятков миллионов строк `reviews`.
  Партиционирование не требуется, план на него описан в FINAL_SPEC §22.
- Метрика `coverage` продуктового блюпринта («доля игр каталога от игр с Metascore
  у источника») считается относительно 18 524 — то есть достижима.

## Risks

| Риск | Митигация |
|---|---|
| Свежая игра ещё без Metascore не попадёт в New Releases | Она попадёт туда в день появления первой рецензии — это и есть момент, когда она становится полезной продукту. Sitemap-сверка ловит остальное |
| `metaScoreMin=1` перестанет поддерживаться источником | Contract-тест на параметры листинга; при отказе — фильтрация на нашей стороне после получения страницы |
| Пользователь ожидает полноты Metacritic | `/about` явно говорит, что мы подмножество источника и не соревнуемся с ним в полноте (позиционирование продукта §1.4) |
