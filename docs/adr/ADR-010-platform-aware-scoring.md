# ADR-010 — Platform-aware данные: модель, получение, подача

**Статус:** принято · 2026-09-06
**Связанные противоречия:** C-04, C-12

## Context

Факт, на котором стоит главный дифференциатор продукта. Cyberpunk 2077 в данных Metacritic:

| Платформа | Metascore | Userscore | n(user) |
|---|---:|---:|---:|
| PC | 86 | 7.3 | 40 140 |
| Xbox Series X | 87 | 7.7 | 641 |
| PS5 | 75 | 8.0 | 1 529 |
| Xbox One | 61 | 5.1 | 4 384 |
| **PS4** | **57** | **3.8** | 10 876 |

Разброс 29 пунктов Metascore и 3.5 балла Userscore внутри одной игры. При этом:

- страница источника по умолчанию показывает lead-платформу;
- `?platform=` **игнорируется** и composer'ом, и HTML-страницей (проверено на 5 платформах
  Elden Ring — везде вернулся lead PS5);
- Release 0 §5.3 подтвердил, что различаются не только числа, но и **состав претензий**:
  на PC спор о дизайне, на PS4 — о работоспособности; шесть изданий прямо не рекомендуют
  покупать PS4-версию.

Продуктовый блюпринт делает из этого «платформу как глобальный контекст сессии» с селектором
в шапке. Дизайн-пакет такого контрола не содержит и решает задачу секцией `By platform`
и фильтром каталога.

## Decision

### 1. Модель данных

`game_platforms` — ассоциативная сущность с собственными атрибутами, а не строка в `games`:

```
game_platforms(
  id, game_id, platform_id, mc_related_game_id, is_lead, release_date,
  metascore_raw, metascore_count, metascore_positive/neutral/negative, critic_sentiment,
  userscore_raw, userscore_count, userscore_positive/neutral/negative, user_sentiment,
  critic_reviews_with_text, user_reviews_with_text,
  critic_reviews_synced_at, user_reviews_synced_at,
  UNIQUE (game_id, platform_id)
)
CREATE UNIQUE INDEX ... ON game_platforms (game_id) WHERE is_lead;
```

Оценки читаются через `ScoreValue` (ADR-002), то есть `null != 0` действует и здесь.
Отзывы и снапшоты висят на `game_platforms`, а не на `games`.

`platforms` — нормализованный справочник (`mc_platform_id`, `slug`, `name`, `code`, `family`,
`sort_order`), сидируется миграцией и пополняется инкрементально из встреченных игр.
`code` — короткий монокод дизайна (`PC PS5 PS4 XSX XBO NSW NS2 MAC LNX IOS AND VR`).

### 2. Получение

| Данные | Источник | Стоимость |
|---|---|---|
| Metascore на платформу | `composer → product.platforms[].criticScoreSummary` | 0 (в том же вызове) |
| Userscore на платформу | `GET /reviews/metacritic/user/games/{slug}/platform/{p}/stats/web` | 1 запрос на платформу |
| Детальные critic-счётчики | `GET /reviews/metacritic/critic/.../stats/web` | только для платформ в бюджете отзывов |

`?platform=` не используется нигде — параметр игнорируется источником.

Итого полный сбор игры с N платформами: `1 + N` запросов минимум.

### 3. Роллапы в `games`

`lead_platform_id`, `lead_metascore`, `lead_userscore`, `best_metascore`, `best_userscore`
и соответствующие счётчики. Пересчитываются **в той же транзакции**, что и запись
`game_platforms`, поэтому рассинхрон невозможен.

Массивов (`platform_ids int[]`) нет — портируемость (ADR-018); фильтр по платформе
делается полу-джойном по индексу `game_platforms(platform_id, game_id)`, что на масштабе
задачи эквивалентно по плану и не требует GIN.

«Основной рейтинг» = lead-платформа, «лучший» = максимум по платформам; API отдаёт оба,
пользователь выбирает базу сортировки (требование ТЗ §7).

### 4. Подача: фильтр (ТЗ) + предпочитаемая платформа (продукт), без нового контрола в топбаре

- **Каталог**: multi-select фильтр `Platform` с counts — ровно как в дизайне
  (`design/PAGES.md §3`). Это и есть требование ТЗ §7 «фильтрация по платформе».
- **Страница игры**: секция `By platform` — строка на платформу с `ScoreChip`
  (`design/PAGES.md §1.5`). Если ни у одной платформы нет оценок — `Pending`-блок
  плюс плоский список платформ; секция **не удаляется**, потому что платформы реальны
  (`EDGE_CASES.md` case 18).
- **Предпочитаемая платформа**: кнопка-звёздочка в строке `By platform`. Значение
  в `localStorage` (`pl-platform`), без аккаунтов. Делает три вещи:
  1. предвыбирает фильтр платформы в каталоге;
  2. подсвечивает свою строку в `By platform`;
  3. включает **вторую строку вердикта**, тоже арифметическую:
     «On PlayStation 4 critics rate this 29 points lower than on PC.»
- Никаких новых элементов в топбаре — IA дизайна сохранена.

Правило дизайна соблюдено: рядом с числом **всегда** подписана платформа, даже когда она выбрана.

### 5. Резюме — тоже per-platform

Снапшоты и резюме привязаны к `(game_id, platform_id, audience)`. Это то, что даёт
эффект Release 0 §5.3: на PC и PS4 у Cyberpunk разные резюме, потому что разные корпуса.
Для игр с одной платформой это ничего не усложняет.

## Alternatives considered

| Вариант | Почему не выбран |
|---|---|
| Платформа строкой в `games` | Прямо запрещено требованием ТЗ §3 и делает killer feature невозможной |
| Одно резюме на игру, без платформы | Убивает главный результат Release 0: на разных платформах разный **состав** претензий, а не только числа |
| Глобальный селектор платформы в топбаре (позиция продукта) | Ломает IA дизайна, который является source of truth для фронтенда; ТЗ этого не требует. Ценность достигнута без нового контрола |
| Скрывать игры без выбранной платформы (позиция продукта, US-004) | Опасно: пользователь молча теряет игры и не понимает почему. Фильтр — явный, с чипом активного фильтра и `Clear all` |
| Запрашивать critic-stats для всех платформ | `N` лишних запросов ради счётчиков, которые нужны только там, где мы собираем отзывы |

## Consequences

- Cyberpunk 2077 = 5 платформ = 6 запросов на базовый сбор + отзывы по 3 платформам бюджета.
  Учтено в SLO.
- Сортировка каталога должна явно указывать базу (`Metascore` / `Player score`) — в дизайне
  это уже так (`COPY.md §5`).
- Исчезнувшая у источника платформа **не удаляется** из `game_platforms` — история важнее;
  такая строка просто перестаёт обновляться.

## Risks

| Риск | Митигация |
|---|---|
| Пользователь видит оценку не своей платформы | Платформа подписана рядом с каждым числом; предпочитаемая платформа подсвечена; вторая строка вердикта явно называет расхождение |
| Разрастание `game_platforms` × `summaries` | Резюме генерируются только для платформ в бюджете отзывов (ADR-005), обычно 1–3 на игру |
| `localStorage` недоступен (приватный режим) | Чтение и запись обёрнуты в `try/catch`; при отсутствии значения продукт работает как в дизайне — по lead-платформе |
