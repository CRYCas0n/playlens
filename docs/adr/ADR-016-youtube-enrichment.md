# ADR-016 — YouTube Let's Play: изолированное обогащение с деградацией

**Статус:** принято · 2026-09-06
**Уточняет:** `BLUEPRINT.md §12`, `PRODUCT_BLUEPRINT.md §18`
**Связанные противоречия:** C-17

## Context

ТЗ Bonus 1: найти Let's Play, выбрать наиболее популярный релевантный ролик, получить
транскрипт, сделать summary, показать вывод и ссылку. Дизайн содержит спроектированную
секцию «See it played» (`PAGES.md §1.8`).

Эмпирика `BLUEPRINT.md §2.2.2` (пошаговая проверка на реальном видео):

1. `GET /watch?v=...` → 200, в HTML **есть** `captionTracks` с дорожкой `en/asr`;
2. `baseUrl` содержит валидную серверную подпись;
3. запрос по этому `baseUrl` → **HTTP 200, длина тела 0 байт**;
4. то же с `fmt=json3|srv3|vtt`, `c=WEB`, `potc=1` → **200, 0 байт во всех случаях**;
5. InnerTube `/youtubei/v1/player` с клиентом ANDROID → HTTP 400.

Вывод: требуется proof-of-origin token; без него `timedtext` возвращает **пустоту молча** —
не ошибку, а пустой 200. Это самая коварная форма отказа: наивный код решит «субтитров нет».

Официальный `captions.download` требует OAuth **владельца канала** — для чужих роликов
неприменим. Data API даёт только булев `contentDetails.caption`.

Квота: `search.list` = **100 units**, лимит 10 000/сутки → **~100 поисков в сутки**.
`videos.list` = 1 unit на до 50 id.

Продуктовая оценка (§18): худший показатель Value × Confidence / Effort в проекте;
26 SP при value 2–3; первый кандидат на вырезание.

## Decision

**Реализуется полностью как код. Выключено по умолчанию. Полностью изолировано от основного
конвейера.**

### 1. Изоляция отказа

`youtube.*` — отдельные типы задач в очереди `enrich`. Ни одна из них не является
предусловием для `game.sync`, `reviews.sync`, `summary` или `similarity`.
Падение, квота, таймаут или пустой транскрипт **не влияют** на статус игры.
Это Сценарий 3 ТЗ §30: «YouTube quota exhausted → данные игры не считаются failed».

### 2. Гейт перед тратой квоты

```
best_metascore IS NOT NULL
AND (best_metascore >= YT_MIN_SCORE (60) OR user_reviews_with_text >= 50)
AND youtube_searched_at IS NULL
```

Один `search.list` на игру **за всё время жизни**; повторный поиск — только по явной команде
оператора или по расписанию для игр без найденного видео старше `YT_RESEARCH_AFTER_DAYS`.

### 3. Отбор ролика — три барьера против трейлера

| Барьер | Механизм |
|---|---|
| 1 | `videoDuration=long` прямо в `search.list` (>20 мин) — бесплатно отсекает Shorts и трейлеры |
| 2 | хард-фильтр `duration_s < YT_MIN_DURATION_S` (600) |
| 3 | regex по названию: `trailer\|teaser\|announcement\|reveal\|cinematic` |

Плюс отсев: `liveBroadcastContent != 'none'`; `duration_s > YT_MAX_DURATION_S` (25 200);
`review\|tier list\|news\|ost\|soundtrack\|speedrun\|all cutscenes\|the movie\|tips\|guide\|
how to\|best settings\|benchmark\|fps test\|mods\|ranking`; пересечение токенов названия
с названием игры `< 0.6`; `defaultAudioLanguage` вне `YT_ALLOWED_LANGS`;
`embeddable = false` **и** `caption = false` одновременно.

Отсеянный ролик всё равно записывается в БД с `rejected_reason` — иначе разбор невозможен.

### 4. Ранжирование: «самый популярный» ≠ «первый результат»

```
score = 0.32 * popularity      # log10(views+1) / log10(max_views+1)
      + 0.28 * title_relevance # 0.6*token_overlap + 0.4*lp_keyword_score
      + 0.14 * format_fit      # колокол по длительности, пик 30 мин - 3 ч
      + 0.12 * engagement      # min(1, (likes/views) / 0.05)
      + 0.08 * recency_fit     # exp(-|upload - release| / 120d); 0 если раньше релиза
      + 0.06 * series_signal   # 1.0 если >=3 ролика того же канала среди кандидатов
      - penalties
```

Штрафы: `-0.25` за `no commentary` (**нечего суммаризировать** — ключевой нюанс именно нашей
задачи), `-0.15` за `#shorts`, `-0.10` за компиляции, `-0.20` при `caption == false`.
Тай-брейк — «part 1 / episode 1»: начало прохождения характеризует игру, а не позднюю главу.

Вес просмотров — 0.32 из 1.0 и логарифмический: ролик с 7M просмотров, но `no commentary`
и слабым совпадением названия проигрывает 150-тысячнику с явным «Let's Play … Part 1».

### 5. Каскад транскриптов и главное правило

```python
for provider in PROVIDERS:            # ytdlp -> hosted_api -> asr -> metadata_only
    if not provider.enabled: continue
    try:
        t = provider.fetch(video)
        if t and t.char_count >= YT_MIN_TRANSCRIPT_CHARS:   # 2000
            save(status='available', source=provider.name); return t
        record_attempt(provider, ok=False, error='empty_or_too_short')   # <-- НЕ успех
    except ProviderError as e:
        record_attempt(provider, ok=False, error=str(e))
save(status='unavailable')
```

> **HTTP 200 с нулевым телом — это ОШИБКА ПРОВАЙДЕРА, а не «субтитров нет».**

Это отдельный юнит-тест на фикстуре `transcript_empty_200`, воспроизводящей найденный дефект.
Все попытки пишутся в `youtube_transcripts.attempts jsonb` — без этого каскад неотлаживаем.
`transcript_source` (`ytdlp` / `hosted_api` / `asr` / `metadata_only`) хранится и доходит до UI.

### 6. Деградация в UI (правила дизайна)

| Что доступно | Что показываем |
|---|---|
| Транскрипт получен | Spoiler-free впечатление + `[YouTube] [AI summary] Written from the 3:12:44 video, not from reviews` |
| Только метаданные | Ссылка на ролик + название, канал, длительность. **AI-выводов нет** |
| Ролик не найден | **Секция удаляется целиком вместе с якорем** (`EDGE_CASES.md` case 12) |

**Категорически запрещено** генерировать «впечатление от геймплея» по названию ролика —
чистая галлюцинация при минимальной пользе (`PRODUCT_BLUEPRINT §18`).

### 7. Спойлеры

Четыре уровня: (1) промпт прямо запрещает упоминать сюжетные события, персонажей, боссов
и концовку — разрешены темп, сложность, управление, техническое состояние, объём;
(2) выборка предпочитает ранний геймплей; (3) UI держит блок свёрнутым и ниже всего,
спойлерная часть за `SpoilerShield` (размыта, `pointer-events: none`, раскрывается кнопкой);
(4) честность: «Spoiler-free» заявляется как намерение, а не гарантия, и ссылка на ролик
сопровождается предупреждением, что в самом ролике спойлеры есть.

### 8. Выключено по умолчанию

`YOUTUBE_ENABLED=false` в `.env.example`: ключа YouTube Data API нет (**OQ-B2**),
а работоспособность PO-token пути в целевой инфраструктуре не проверена (**OQ-V5**).
Включение — одна переменная плюс ключ. Код, тесты и фикстуры присутствуют и проходят.

## Alternatives considered

| Вариант | Почему не выбран |
|---|---|
| Не делать Bonus 1 вовсе | ТЗ его содержит; отказ без попытки — невыполненное требование |
| Сделать и включить по умолчанию | Без ключа сервис при первом запуске выдавал бы ошибки квоты в мониторинге, создавая впечатление поломки |
| Один провайдер транскриптов | Ни один не даёт приемлемой надёжности — доказано эмпирически |
| Скрейпинг выдачи YouTube как основной путь | Локализованные строки вместо чисел, нет `liveBroadcastContent` и `caption`, капчи с датацентровых IP, ToS-серая зона. Оставлен выключенным fallback при исчерпании квоты |
| Показывать транскрипт пользователю | 20 000+ слов междометий. Транскрипт — сырьё для модели, не контент (`PRODUCT_BLUEPRINT §18`) |
| Резюме по описанию ролика при отсутствии транскрипта | Прямо запрещено: галлюцинация с максимальным репутационным риском |

## Consequences

- Ожидаемое покрытие транскриптами без платного провайдера — **30–60%**
  (`PRODUCT_BLUEPRINT §25` прямо исключает эту метрику из Data Quality Score, чтобы она
  не окрашивала здоровую систему в красный).
- Практический потолок Data API: ~94 игры в сутки (94 × 101 = 9 494 units при бюджете 9 500).
- `ASR`-провайдер (`faster-whisper`) описан, но зависимость не устанавливается по умолчанию:
  3 часа видео ≈ 10 минут CPU и заметный трафик.

## Risks

| Риск | Митигация |
|---|---|
| Транскрипт недоступен (подтверждённый риск) | Каскад + `metadata_only` + удаление секции; ссылка и метаданные сохраняются всегда; статус виден в БД и в UI |
| Выбран не тот ролик | Три барьера против трейлеров, порог совпадения названия 0.6, фикстурная тест-сюита на 25 кандидатов, `rejected_reason` для разбора |
| Спойлер просочился в spoiler-free блок | Многоуровневая защита; гарантия не обещается; блок свёрнут по умолчанию |
| Квота исчерпана | `api_budgets` посуточно; задача переносится (`next_retry_at` на следующие сутки), а не падает |
| Качество авто-субтитров Let's Play (крики, звукоподражания) | Не проверено — OQ-V6; при провале фича понижается, основной продукт не затронут |
