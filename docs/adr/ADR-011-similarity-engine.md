# ADR-011 — Похожие игры: объяснимый гибрид без нейросетевых эмбеддингов

**Статус:** принято · 2026-09-06
**Заменяет:** `BLUEPRINT.md §11` (ADR-0005) в части embedding-компонента и pgvector
**Связанные противоречия:** C-14, C-21

## Context

ТЗ §6 требует: похожие игры выбираются **только среди игр, уже присутствующих в нашей БД**;
рассмотреть варианты и обосновать выбор; эффективно хранить и вычислять; показывать в карточке
игры кликабельными.

Дизайн добавляет жёсткое правило (`README.md §3 п.8`, non-negotiable):

> «Similarity reasons are rendered only when the backend supplies one. `similarityReason: null`
> renders nothing. **Never invent a reason.**»

и (`EDGE_CASES.md` case 14): при отсутствии достаточно близких игр — честный `EmptyState`,
**никогда не добивать список слабо связанными играми**.

Продуктовый блюпринт §17: без объяснения похожести фича имеет **отрицательную** ценность.

Блюпринт предлагал гибрид metadata + локальные эмбеддинги (`bge-small-en-v1.5` через
`fastembed`/ONNX) + pgvector с HNSW. При этом сам же отмечал (§11.1), что гибрид «работает
даже когда эмбеддингов ещё нет», а в формуле §11.2 уже присутствует `aspect_similarity` —
косинус по `aspect_verdicts` из AI-резюме.

## Decision

**Гибрид из трёх объяснимых компонентов. Нейросетевых эмбеддингов и pgvector в MVP нет.**

```
S(a,b) = 0.62 * M(a,b) + 0.26 * A(a,b) + 0.12 * L(a,b)

M — metadata (детерминированный, объяснимый):
      0.30 * Jaccard(genres)
    + 0.20 * max(franchise_match, family_match)      # 1.0 при одной франшизе
    + 0.16 * company_overlap                          # developer 1.0, publisher 0.5
    + 0.12 * Jaccard(platforms)
    + 0.12 * score_proximity                          # 1 - |meta_a - meta_b| / 100
    + 0.10 * era_proximity                            # exp(-|dyears| / 6)

A — aspect profile (из AI-резюме):
    косинус по 15-мерному вектору aspect_verdicts,
    где positive=+1, mixed=0, negative=-1, absent=0 (и не участвует в норме)

L — lexical (по similarity-документу):
    сходство по нормализованным токенам title/genres/description
```

Множители-штрафы:
- `x0.35`, если у **обеих** игр нет Metascore и меньше 5 пользовательских отзывов —
  не рекомендуем пустышки;
- `x0.5` для DLC/переиздания той же `mc_family_id` (Elden Ring ↔ Shadow of the Erdtree) —
  показывать стоит, но не занимать ими весь топ;
- хард-фильтр `similar_game_id <> game_id`.

**Порог публикации** `SIMILARITY_MIN_SCORE = 0.34`. Ниже порога игра не показывается,
даже если это оставит пустой блок. Это прямое требование дизайна и продукта.

### Объяснение похожести — вычисляется, а не выдумывается

`similar_games.components jsonb` хранит вклад каждого компонента. `reason` генерируется
детерминированным правилом по **самому сильному** компоненту, и только если его вклад
выше `REASON_MIN_CONTRIBUTION`:

| Условие | Reason |
|---|---|
| одна франшиза | `Same series` |
| общий разработчик | `Same studio` |
| Jaccard(genres) >= 0.6 | `Similar genre and tone` |
| aspect-косинус >= 0.7 и общий сильный аспект | `Players praise both for {aspect}` |
| score_proximity >= 0.9 и обе с оценками | `Similar critic reception` |
| иначе | `null` — чип не рендерится |

Никакого LLM в объяснении: правило детерминировано, проверяемо и не может соврать.
`null` — легитимный результат, дизайн его предусматривает (`EDGE_CASES.md` case 15).

### Вычисление: две фазы

**Фаза 1 — кандидаты (SQL, дёшево)**, до `SIMILARITY_CANDIDATE_LIMIT` (300) через UNION:
по пересечению жанров (топ по `best_metascore`), по общему разработчику, по франшизе/семье,
по близости оценки в том же основном жанре.

**Фаза 2 — точный скоринг** кандидатов в Python, top-`SIMILARITY_TOP_N` (12) пишется
в `similar_games` через `DELETE + INSERT` в одной транзакции (идемпотентно, без окна пустоты).

Полная матрица N² невозможна и не нужна.

**Когда пересчитывать:** после `game.sync` с изменившимся fingerprint'ом; после успешной
генерации резюме (меняется aspect-профиль); плюс суточная `similarity.refresh_stale`
для игр с `similarity_synced_at < now() - SIMILARITY_REFRESH_STALE_DAYS` (7) —
новая игра меняет топ у соседей, и мгновенная симметрия стоила бы слишком дорого.
Это документированный компромисс.

## Alternatives considered

| | A. Metadata only | B. Embeddings only | C. Metadata + ONNX-эмбеддинги (блюпринт) | **D. Metadata + aspect + lexical (выбрано)** |
|---|---|---|---|---|
| Стоимость | $0 | модель 130 МБ + runtime 250 МБ | то же | **$0, ноль новых зависимостей** |
| Холодный старт | нет | есть | частично | **нет** |
| Объяснимость | полная | **никакой** | частичная | **полная — каждый компонент называется словом** |
| Различает souls-like и action-RPG про фермерство | нет | да | да | **да, через aspect-профиль и лексику** |
| Требует pgvector | нет | да | да | **нет** |
| Как выглядит провал | «все Action» | случайная выдача | — | деградирует до A |

Выбран D. Ключевой довод: `aspect_verdicts` — 15-мерный семантический профиль игры,
который система **уже вычисляет** в рамках обязательного требования ТЗ §5 (AI-резюме).
Он несёт ровно ту информацию, ради которой брали эмбеддинги («похожа по духу»), но при этом
объясним словами и стоит ноль. Тащить 380 МБ зависимостей и расширение БД ради дублирующего
сигнала — прямое нарушение §63 задания.

Отдельно отклонено: использовать `related-carousel` Metacritic. Его `links.self.href`
раскрывает реализацию — `finder?sortBy=-metaScore&genres=Action+RPG&limit=24`, то есть
«топ жанра». Для Elden Ring выдаёт Hades II и Mass Effect 3.

## Consequences

- До появления AI-резюме компонент `A` равен нулю и веса перенормируются — система едет
  на metadata + lexical. Это соответствует §11.1 блюпринта.
- Качество прямо зависит от размера каталога → seed-обход обязателен (ADR-014).
- `EmbeddingProvider` описан как точка расширения: добавление внешнего или локального
  провайдера = новая реализация интерфейса + четвёртый компонент в формуле, без изменения
  остального.
- `game_embeddings` и pgvector в схеме MVP отсутствуют — миграция при добавлении будет
  аддитивной.

## Risks

| Риск | Митигация |
|---|---|
| Похожие не кажутся похожими (PV3 не проверена) | Порог; честный пустой блок; `components` в API позволяет разбирать конкретный случай; ручная проверка топ-20 — приёмочный критерий фазы |
| Aspect-профиль отсутствует у большинства игр на старте | Веса перенормируются; фича не ломается, только теряет точность |
| Порог 0.34 подобран, а не измерен | Вынесен в конфиг; фиксируется как OQ-N2 с планом калибровки на реальном каталоге |
| Симметрия отложена на сутки | Документированный компромисс; для новых игр пересчёт немедленный, для соседей — суточный |
