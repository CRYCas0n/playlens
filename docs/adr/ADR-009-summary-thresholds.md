# ADR-009 — Пороги генерации резюме и политика перегенерации

**Статус:** принято · 2026-09-06
**Уточняет:** `PRODUCT_BLUEPRINT.md §14`, `BLUEPRINT.md §10.4`
**Связанные противоречия:** C-08

## Context

Продуктовый блюпринт задал одно правило: «<20 отзывов → вердикт не генерируется».
Задание требует проверить его, а не принимать автоматически: одинаков ли порог для критиков
и игроков; что делать с 5 качественными рецензиями критиков; что делать со 100
низкокачественными пользовательскими.

Release 0 §5.4 уточнил: считать надо **по числу отзывов с текстом**, а не по числу оценок.
Onimusha — 77 пользовательских оценок, из них 10 с текстом; Userscore 8.7 выглядит
достоверно, но суммаризировать нечего.

Перепроверка всех 21 корпусов Release 0 показала форму распределения:

| Слой | Пример | critic-текстов | user-текстов |
|---|---|---:|---:|
| крупные релизы | Cyberpunk PC | 92 | 9 136 |
| средние | Skull and Bones | 50 | 158 |
| свежие | Onimusha | 89 | 10 |
| инди/мелкие | BioEden | 4 | 0 |
| | NBA 2K27 | 5 | 0 |

Единый порог 20 отрезал бы critic-резюме у NBA 2K27 и BioEden — при том что 5 рецензий
изданий это осмысленный корпус, а Release 0 на малых корпусах (<20) показал **91.7%**
прохождения claim-level.

## Decision

### Пороги асимметричны и считаются по текстам после фильтра корпуса

| Что генерируем | Условие |
|---|---|
| Резюме критиков | `snapshot(critic).review_count >= SUMMARY_MIN_CRITIC_REVIEWS` = **5** |
| Резюме игроков | `snapshot(user).review_count >= SUMMARY_MIN_USER_REVIEWS` = **20** |
| Объяснение gap'а | обе стороны выше своих порогов **и** `abs(gap_normalized) >= GAP_MIN_POINTS` (7) |
| Строка вердикта | **всегда** — она арифметическая и не требует корпуса (ADR-012) |

Считается `review_count` **снапшота**, то есть уже после фильтра качества (ADR-007), а не
`totalResults` источника и не число оценок.

Ниже порога — не деградация, а явное состояние `skipped_no_data`, которое UI рендерит как
`Waiting` / «Nothing to summarise yet» с указанием, сколько отзывов уже проиндексировано
(`design/COPY.md §8`).

### Обоснование асимметрии

Это не подгонка, а разная природа корпусов:

| | critic | user |
|---|---|---|
| Кто пишет | издание, редактура, подпись | аноним |
| Средняя длина текста в корпусах Release 0 | сотни символов, содержательные | от «10/10 огонь» до эссе |
| Загрязнение | практически нет | пять задокументированных паттернов (Release 0 §5.1) |
| Независимость | разные издания = разные наблюдатели | тысячи отзывов могут быть одной кампанией |
| Сколько нужно для `>= 3` независимых подтверждений на claim | 5 достаточно | нужен запас на отбраковку |

### Политика перегенерации

```python
def should_regenerate(game, platform, audience) -> Decision:
    snap = build_or_get_snapshot(...)
    if snap.review_count < threshold(audience):
        return SKIP("skipped_no_data")
    fp = fingerprint(snap.content_hash, prompt_version, model, params_version)
    if exists(summaries WHERE game, platform, audience, input_fingerprint == fp):
        return SKIP("identical_input")             # физически защищено UNIQUE
    cur = current_summary(...)
    if cur is None:                    return GENERATE("first")
    if snap.content_hash != cur.snapshot.content_hash:
        new = snap.review_count - overlap(snap, cur.snapshot)
        if new >= AI_MIN_NEW_REVIEWS:                 return GENERATE("new_reviews")     # 10
        if new / snap.review_count >= AI_MIN_NEW_RATIO: return GENERATE("new_ratio")     # 0.20
    if score_moved(game, platform, audience) >= AI_SCORE_MOVE_POINTS:
        return GENERATE("score_moved")                                                   # 3 пункта на оси 0-100
    if cur.status in ("failed", "rejected") and retry_window_passed(cur):
        return GENERATE("retry_after_failure")
    if age(cur) > AI_MAX_SUMMARY_AGE_DAYS and new > 0:  return GENERATE("staleness")      # 90
    return SKIP("not_enough_change")
```

`input_fingerprint = sha256(snapshot.content_hash + prompt_version + model + params_version)`
и `UNIQUE(game_id, platform_id, audience, input_fingerprint)` — **последний рубеж**:
даже при ошибке в логике выше повторный вызов с тем же входом физически не дойдёт до LLM.

Порог `AI_SCORE_MOVE_POINTS = 3` соответствует продуктовому правилу «пересчёт при сдвиге
оценки ≥0.3» (`PRODUCT_BLUEPRINT §16`), переведённому на ось 0–100.

## Alternatives considered

| Вариант | Почему не выбран |
|---|---|
| Единый порог 20 для обеих аудиторий | Отрезает critic-резюме у инди и свежих релизов, где 5 рецензий изданий — полноценный корпус. Данные Release 0 на малых корпусах дают 91.7% |
| Порог по числу оценок, а не текстов | Onimusha: 77 оценок, 10 текстов. Порог сработал бы, суммаризировать было бы нечего |
| Порог по `totalResults` источника до фильтра | Игра со 100 спам-отзывами прошла бы порог и дала бы резюме по спаму |
| Нет порога, генерировать всегда с пометкой «мало данных» | Прямо противоречит принципу «Лучше отказаться, чем угадать» и создаёт главный репутационный риск R3 |
| Динамический порог от разброса оценок | Красиво, но необъяснимо пользователю и невозможно протестировать таблично. Отложено |
| Пересчёт по расписанию | Часовой цикл жёг бы бюджет впустую; пересчёт по дельте — требование `PRODUCT_BLUEPRINT §16` |

## Consequences

- Часть игр (свежие инди без отзывов) останется без резюме игроков — **это осознанный
  отказ от фичи, а не деградация** (PQ5 продуктового блюпринта: «да — ложный вердикт хуже
  отсутствующего»).
- Метрика `summary_availability` (доля игр с резюме от игр, где оно возможно) считается
  относительно порогов, а не абсолютно — иначе она всегда красная.
- Пороги вынесены в конфиг и покрыты табличными тестами на граничных значениях (4/5/6 и 19/20/21).

## Risks

| Риск | Митигация |
|---|---|
| Порог 5 для критиков даёт слабое резюме на 5 коротких цитатах | Валидатор требует `>= 2` независимых подтверждений на малых корпусах; claims без поддержки отбрасываются; при полной отбраковке резюме не публикуется |
| Пользователь воспринимает отсутствие резюме как поломку | Копирайт дизайна разделяет «пока нет» и «сломалось» (`COPY.md §8/§9`); указывается, сколько отзывов уже есть и когда ждать |
| `AI_SCORE_MOVE_POINTS = 3` слишком чувствителен на малых выборках | Дополнительное условие: сдвиг учитывается только при `review_count >= LOW_SAMPLE_THRESHOLD` |
