# Deployment

> **Looking for a free host?** See [`DEPLOYMENT_OPTIONS.md`](DEPLOYMENT_OPTIONS.md).
> Render's free tier does not include a worker, so a full Render deployment costs about
> $22/month. Hugging Face Spaces plus Neon is free and needs no card.

The service needs six things from a host: managed PostgreSQL, one web process, one
long-running worker, one hourly schedule, environment secrets and HTTPS on a public name.
That list is short and unremarkable, and it is what the options below are judged against.

**Nothing here has been applied.** No hosting account exists — creating one is the
owner's action — so every file in this document is written to a published schema, parses,
and has never run. Treat the first deploy as a test of these files.

**Render is the recommendation only if you are paying.** `render.yaml` in the repository
root is written for it and describes the whole stack in one file, which is genuinely the
smoothest paid path — three services and a database from one click.

It is **not** the free path, and I recommended it as one by mistake. Its free tier covers
a web service and a database; there is no free worker plan, and this service needs a
worker. A real Render deployment is about $22/month.

Its other limits, while we are being exact:

* The free PostgreSQL plan **expires after 30 days**.
* The free web plan **sleeps after 15 minutes** of no traffic, waking in ~30 seconds.

**For free, see [`DEPLOYMENT_OPTIONS.md`](DEPLOYMENT_OPTIONS.md):** Hugging Face Spaces
for the app and Neon for the database, neither of which asks for a card. That path runs
all three roles in one container (`app/allinone.py`), which is a compromise the document
names and quantifies.

A VPS is the other honest option if you already have one: `docker compose up -d` with the
production overlay does the whole thing.

## Deploying to Render

**What you need:** a GitHub account (you have one) and a Render account.

1. **Sign up** at <https://render.com> with GitHub. No card for the free tier.
2. **New → Blueprint.** Pick the `playlens` repository. Render reads `render.yaml` and
   shows four resources: a database, a web service, a worker and a cron job.
3. **Two values are asked for**, because they are deliberately not in the file:
   - `LLM_API_KEY` — your OpenAI key
   - `YOUTUBE_API_KEY` — your YouTube Data API key
   `ADMIN_TOKEN` is generated by Render; you never see or set it.
4. **Apply.** First build is 5–10 minutes.

Migrations run automatically: the image's entrypoint runs `alembic upgrade head` for the
`api` role only, so exactly one process ever holds Alembic's lock.

### What to check when it finishes

```
https://playlens.onrender.com/api/v1/health     -> {"status":"ok"}
https://playlens.onrender.com/                  -> the catalogue, empty at first
https://playlens.onrender.com/admin/monitoring  -> the pipeline, no runs yet
```

The catalogue is empty until the first crawl. The cron job fills it at seven minutes past
the hour, twenty games at a time. To not wait:

```
Render dashboard -> playlens-crawl -> Trigger Run
```

## Deploying to a VPS

For a machine you already have. Needs Docker and about 2 GB of RAM.

```bash
git clone https://github.com/CRYCas0n/playlens.git && cd playlens
cp .env.example .env && nano .env          # ADMIN_TOKEN, LLM_API_KEY, YOUTUBE_API_KEY
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build
docker compose logs -f api
```

The production overlay adds restart policies, resource limits and log rotation, and
requires every credential rather than defaulting it. The base file does not publish the
database port on any profile, so forgetting the overlay cannot expose PostgreSQL.

Then put a reverse proxy in front of port 8000 for TLS — Caddy is two lines:

```
playlens.example.com {
    reverse_proxy localhost:8000
}
```

## Before it is public

Three things, in order of how much they matter.

**1. The legal question is not technical.** The service reads Metacritic through an
interface Metacritic publishes for its own site. Their terms discourage automated
collection. On your own machine, for a portfolio, that is ordinary. On a public address it
is a different question, and it is about your risk rather than the code. What the code
does about it: two requests a second, an identifying User-Agent, review text never
republished in full, and a not-affiliated notice on every page. What it cannot do is make
the decision. See `OQ-B3`.

**2. Set a real cost ceiling.** `AI_DAILY_COST_LIMIT_USD` defaults to 10 and is enforced
before each model call, not merely displayed. Decide the number deliberately.

**3. The admin token is one shared secret with no rotation.** Adequate for one operator,
not for a team. `POST /api/v1/admin/*` is everything a token protects; monitoring reads
are deliberately open, and their error text passes through the same redactor as the logs.
