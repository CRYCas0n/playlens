## 3. Правило разрешения конфликтов

Применяется порядок из задания §62, но не механически: каждое решение обязано быть обосновано и зафиксировано в ADR.

1. Обязательное требование исходного ТЗ.
2. Доказанный факт исследования (fixtures > текст документа).
3. Security / legal.
4. Корректность данных.
5. Продуктовая ценность.
6. UX.
7. Простота архитектуры.
8. Оптимизации и бонусы.

**Более позднее проверенное исследование побеждает более раннее.** Release 0 (2026-09-06) > BLUEPRINT §2 (2026-09-05) там, где они расходятся.

## 4. Что НЕ переписывается

`BLUEPRINT.md`, `PRODUCT_BLUEPRINT.md`, `RELEASE0_VALIDATION.md`, `research-fixtures/`, `design/` — история принятия решений и первичные данные. Они остаются как есть. Все изменения решений живут в `docs/adr/` и `docs/FINAL_SPEC.md`.
